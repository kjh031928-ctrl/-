## 질문 1. 어떤 ML 모델을 썼고 어떻게 학습시켰나

### 1-1. 한 줄 요약 (먼저 이렇게 답한다)

> "총 17개 기법을 시험했고, **로짓변환 선형회귀**를 최종 채택했습니다.
> 나머지 16개는 전부 탈락시켰으며, 탈락 사유를 기법별로 기록했습니다."

핵심은 "이거 하나 썼습니다"가 아니라 **"다 해보고 이걸 골랐습니다"**이다.
탈락 기록이 있다는 게 이 프로젝트의 강점이므로 먼저 꺼낸다.

### 1-2. 채택 모델 — 로짓변환 선형회귀

**선형회귀부터.**

> 점들이 흩어져 있을 때 그 사이를 가장 잘 지나가는 직선을 긋는 방법입니다.
> "가장 잘"의 기준은 **각 점에서 직선까지의 세로 거리를 제곱해서 다 더한 값이 최소**가
> 되는 것입니다. 이걸 최소제곱법(OLS)이라고 합니다.

변수가 3개니까 직선이 아니라 3차원 공간의 평면이다. 식은 이렇다.

```
전환율 = b₀ + b₁·(입구온도) + b₂·(프로펜유량) + b₃·(벤젠/프로펜 비율)
```

학습이란 데이터에 가장 잘 맞는 `b₀, b₁, b₂, b₃` 네 숫자를 찾는 것이다.
반복 계산이 아니라 **공식 한 번으로 정확히 계산**된다(해가 닫힌 형태로 존재).
그래서 랜덤성이 없고 몇 번 돌려도 같은 값이 나온다.

**여기에 왜 로짓을 씌웠나.**

> 전환율은 정의상 0과 1 사이입니다. 그런데 그냥 직선을 그으면 356°C부터
> 1을 넘어버렸습니다. 100% 넘게 반응한다는 물리적으로 불가능한 예측입니다.

그래서 **직선을 긋기 전에 y축을 늘려놓는다.**

```
1단계  z = ln( X / (1−X) )          0~1 이던 값이 −∞ ~ +∞ 로 펴짐
2단계  z 에 대해 선형회귀             펴진 공간에서 직선 긋기
3단계  X = 1 / (1 + e^(−z))         다시 0~1 로 접어 넣음 (시그모이드)
```

3단계에서 쓰는 시그모이드 함수는 **수학적으로 절대 0~1을 벗어날 수 없다.**
그래서 아무리 외삽해도 물리적으로 불가능한 값이 나오지 않는다.

> **주의 — 로지스틱 회귀와 다르다.**
> 로지스틱 회귀는 "암이다/아니다" 같은 **분류**용이고 y가 0 또는 1이다.
> 우리는 y가 0.31~0.85의 **연속값**이고, 최소제곱으로 적합한다.
> 같은 시그모이드를 쓰지만 목적도 적합 방법도 다르다.
> 통계학에서는 이 방법을 **로짓변환 선형회귀**라고 부른다.

### 1-3. GBR (Gradient Boosting Regression) — 물어보면 이렇게

> **한 줄:** 약한 예측기를 여러 개 만들어서, 뒤엣것이 앞엣것의 실수를 고쳐나가는 방식입니다.

단계별로 설명하면 이렇다.

```
1. 아주 단순한 결정트리를 하나 만든다 (예: "온도 345도 넘으면 0.7, 아니면 0.5")
   → 당연히 많이 틀린다
2. 얼마나 틀렸는지(=잔차)를 계산한다
3. 이번엔 "정답"이 아니라 "1번의 잔차"를 맞히는 트리를 새로 만든다
4. 두 트리의 예측을 더한다 → 아까보다 조금 정확해짐
5. 다시 남은 잔차를 맞히는 트리를 만든다 ... 이걸 수백 번 반복
```

**"부스팅"**은 약한 것들을 쌓아 강하게 만든다는 뜻이고,
**"그래디언트"**는 3번에서 잔차를 줄이는 방향을 미분으로 찾는다는 뜻이다.

**결정트리**는 "온도가 X보다 큰가?" 같은 예/아니오 질문을 반복해 데이터를 칸으로 나누고,
각 칸마다 그 칸에 속한 데이터의 평균값을 답으로 내놓는 구조다.

**우리가 GBR을 탈락시킨 이유가 바로 이 구조에 있다.**

> 트리는 학습할 때 본 범위를 칸으로 나눕니다. 학습 데이터의 최고 온도가 350°C였으면
> "350°C 초과" 칸이 마지막 칸이고, 거기 담긴 답은 350°C 근처 데이터의 평균 하나뿐입니다.
> 그래서 360°C를 물어도 370°C를 물어도 **같은 답**이 나옵니다.

이걸 **외삽 평탄화(flattening)**라고 기록해뒀다. 우리 케이스 스터디가 365°C 예측을
요구하므로 이 성질은 치명적이다. GBR 검증 오차는 로짓 선형의 약 4배였다.

### 1-4. 시험한 17개 기법과 탈락 사유

| 기법 | 쉬운 설명 | 탈락 사유 |
|---|---|---|
| 1차 선형(무처리) | 그냥 직선 | 356°C부터 X>1 물리위반 |
| 1차+하드클립 | 직선 긋고 1 넘으면 잘라냄 | 위반을 가릴 뿐(원시값 1.27) |
| **로짓 1차** | **직선+시그모이드로 0~1 보장** | **채택** |
| 로짓 2차 | 로짓공간에서 곡선 | 좁은 학습구간→외삽 발산 |
| 2차 다항 | 포물선 | 외삽에서 폭주 |
| Ridge | 직선인데 계수가 커지면 벌점 | 정규화 실익 없음 |
| Lasso | 위와 같은데 불필요한 변수는 0으로 | alpha↑ 시 계수 붕괴 |
| GBR | 잔차를 반복해서 고침 | 외삽 평탄화 |
| RandomForest | 트리 수백 개의 평균 | 외삽 평탄화 |
| ExtraTrees | RF인데 분할을 더 무작위로 | 외삽 평탄화 |
| HistGBM | GBR의 빠른 버전 | 외삽 평탄화 |
| KNN | 가장 비슷한 이웃 k개의 평균 | 외삽 평탄화 |
| SVR | 오차 허용 띠 안에 들어가는 선 | 외삽 시 평균으로 회귀 |
| MLP | 신경망 | 불안정, X>1 위반(365°C에서 1.949) |
| GPR | 확률적 곡선 추정 | 외삽 시 사전평균(0)으로 붕괴 |
| 입력변환 1/T | 아레니우스 형태 | T와 1/T 상관 −0.99992로 무효 |
| 입력변환 1/FT | 체류시간 형태 | 성능 악화 |

**탈락 사유가 5가지 유형으로 정리된다** — 이 구조를 설명하면 깊이가 드러난다.

1. **평탄화** — 트리·근접 계열. 학습범위 밖에서 상수 고정. 구조적 한계
2. **발산** — 다항·신경망. 좁은 구간의 곡률이 외삽에서 폭주
3. **물리위반** — X>1 예측
4. **공선 무효** — 운전범위가 좁아 새 변수가 기존 변수와 거의 같아짐
5. **평균회귀** — 커널 계열. 학습범위 밖에서 평균으로 붕괴

> **핵심 메시지:** 케이스 스터디가 학습범위 밖(365°C) 예측을 요구하므로,
> **정확도만이 아니라 외삽 거동이 동등하게 중요한 선택 기준**이었습니다.

### 1-5. 어떻게 학습시켰나 (절차)

```
분할     시간 순서대로 고정. 무작위 분할 금지
         학습 10/13~16 (1924행) / 검증 10/17-18 (661행) / 10/12는 어디에도 안 씀
조합     입력세트 3종(I1/I2/I3) × 라벨 2종(r0/r1) = 6개 조합을
         모든 기법에 대해 동일하게 실행 → 결과를 results/ 에 JSON 저장
평가     검증셋에서 RMSE·MAE·MAPE·R², 그리고 쿠멘 생산량 오차(kg/h, %)
재현성   seed=42 고정, float64 유지, 모든 설정을 JSON에 기록
```

**무작위 분할을 안 한 이유**를 물으면:

> 공정 시계열 데이터입니다. 1분 간격이라 연속된 두 점이 거의 같습니다.
> 무작위로 섞으면 **거의 같은 데이터가 학습과 검증에 동시에 들어가서**
> 성능이 실제보다 좋게 나옵니다. 그래서 날짜로 잘랐습니다.

## 질문 2. 어떤 데이터를 썼고 무엇을 왜 제외했나

### 2-1. "다 썼습니다"는 틀린 답이다

엑셀은 **29개 컬럼**인데 입력으로 쓴 건 **3개**다.

```
입력 (3개)   TT-1006.PV    반응기 입구온도
             FT-1004.PV    프로펜 유량
             FRC-1004.PV   벤젠/프로펜 질량비
라벨 (2개)   X_propene_conversion (r0), X_propene_recycle1 (r1)
관리용       Timestamp, Campaign, Split, Block_ID
제외         AT-1100, TT-1100, PT-1100, PT-1004, FT-1001/1002/1201/1300,
             dT_adiabatic_C, X_benzene_conversion 등
```

**26개를 뺐고, 뺀 이유가 명확하다.** 이게 답의 핵심이다.

### 2-2. 왜 뺐나 — 정보 누수(leakage)

가장 중요한 논거다. 상관계수를 보여주면 극적이다.

```
corr(TT-1100 출구온도,  전환율) = +0.9755   ← 매우 높음
corr(dT_adiabatic,     전환율) = +0.9683   ← 매우 높음
corr(TT-1006 입구온도,  전환율) = +0.8487
corr(FT-1004 유량,     전환율) = +0.1615   ← 낮음
```

상관계수만 보면 **출구온도를 넣는 게 압도적으로 유리**해 보인다. 그런데 넣으면 안 된다.

> 출구온도가 높은 건 **전환율이 높아서 발열이 많았기 때문**입니다.
> 원인이 아니라 **결과**입니다. 이걸 입력으로 넣으면 "답을 보고 답을 맞히는" 셈입니다.
>
> 게다가 전환율 라벨 자체가 **출구 밀도(AT-1100)를 SRK 상태방정식으로 역산**해서
> 만든 값입니다. 역산 과정에 출구온도·출구압력이 들어갑니다. 즉 이 변수들은
> **라벨 생성 공식에 이미 쓰인 변수**입니다. 입력으로 다시 넣으면 정보 누수입니다.

검증셋 성능은 좋아 보이지만, 실제 예측 상황에서는 **출구온도를 미리 알 수 없다.**
반응이 끝나야 나오는 값이기 때문이다. 쓸 수 없는 정보로 만든 모델이 된다.

### 2-3. 그럼 무슨 기준으로 골랐나 — 인과 기반

> 상관이 아니라 **인과**로 골랐습니다. "전환율을 물리적으로 결정하는 원인"만
> 입력으로 씁니다. 반응기 **입구에서 이미 정해지는 조건** 세 가지입니다.
>
> - 입구온도 → 반응속도를 결정
> - 프로펜 유량 → 체류시간을 결정
> - 벤젠/프로펜 비율 → 반응물 농도비를 결정
>
> 셋 다 반응기 입구에서 관측되므로 **결과(전환율)보다 시간적으로 앞섭니다.**

FT-1004와 FRC-1004가 라벨의 몰수 계산에도 쓰이지만, 이건 **입력 → 라벨** 방향의
물리적 정의이므로 누수와 구분된다.

### 2-4. 압력은 왜 뺐나  *(2026-07-31 전면 재작성)*

> **⚠ 이전 판(“오히려 나빠져서 기각”)은 폐기.** 재검증 결과 나빠진 게 아니라 **차이가 없었고**,
> 압력은 물리적으로 **중요한** 변수였다. 아래가 확정 답변이다.

**먼저 이렇게 답한다 — 이게 가장 강한 표현이다.**

> "압력은 안 중요해서 뺀 게 아닙니다. **물리적으로는 온도 다음으로 센 변수**입니다.
> 저희가 적합한 속도식 기준으로 **반응속도 ∝ 압력^2.31** 입니다.
> 그런데 **이 데이터로는 압력만의 효과를 유량 효과와 떼어낼 수가 없어서** 뺐습니다.
> 그 대가로 생기는 한계도 함께 기록했습니다."

**근거 ① 성능 차이는 “없음”이지 “나빠짐”이 아니다**

```
I1 (T, FT, FRC)          RMSE = 0.02222
I2 (+ PT-1004 공급압력)   RMSE = 0.02235
I3 (+ PT-1100 출구압력)   RMSE = 0.02236
```

차이 0.00013을 그대로 근거로 들면 "오차 범위 아니냐"에 무너진다. 그래서 판정을 붙였다.
1분 간격 데이터라 잔차 자기상관이 1분에 0.997 → 661행은 독립 표본이 아니므로
일반 통계검정을 쓸 수 없다. **60분 블록 부트스트랩 4,000회**로 판정했다.

```
RMSE(I2) − RMSE(I1) = +0.00013,  95% 구간 [−0.00007, +0.00031]  → 0 포함, 차이 없음
RMSE(I3) − RMSE(I1) = +0.00014,  95% 구간 [−0.00005, +0.00031]  → 0 포함, 차이 없음
```

**근거 ② 압력이 왜 성능을 못 올렸나 — 정보가 겹쳐서다**

```
압력을 (TT-1006, FT-1004, FRC-1004)로 회귀   →  R² = 0.9492 (PT-1004, VIF 19.7) · 0.9487 (PT-1100, VIF 19.5)
                                                 압력 고유 정보 = 5.1%
편상관 (양쪽에서 입력 3종 효과 제거 후)       →  PT-1004 +0.1435 / PT-1100 +0.1391
                                                 남은 설명력 ≈ 2%
```

**근거 ③ 압력은 유량의 그림자였다 — 일부러 흔든 날이 하루도 없다**

```
캠페인 안에서 본 corr(PT-1100, FT-1004)
  10/13 (유량만 조작)   +0.9997   ← 사실상 같은 변수
  10/15 (유량+비율)     +0.9252
  10/14 (전부 고정)     +0.0203   ← 여기서만 따로 움직임 (폭 13.2 kPa)
학습셋 전체            +0.7083
```

> 유량을 올리면 촉매층 저항이 커져 압력이 따라 올라갑니다. 압력이 20% 움직였지만
> **그건 압력 실험이 아니라 유량 실험의 부산물**입니다. 그래서 모델이 배우는 압력 계수는
> 사실상 **유량 효과에 압력이라는 이름표를 붙인 것**입니다.

**근거 ④ 케이스 스터디에서 압력 값을 줄 수 없다**

문제(§3.3-6)는 온도 335–365°C, 유량 15,000–18,000 kg/h, 비율 4–6만 지정한다. 압력은 없다.
게다가 시뮬레이션에서 반응기 압력은 우리가 넣는 값이 아니라 **플로우시트가 계산해 내놓는 값**이다.
압력을 ML 입력으로 받으면 "압력을 알아야 전환율을 알고, 전환율을 알아야 압력을 안다"는
순환 의존이 생긴다.

**근거 ⑤ PT-1100은 원인이 아니라 결과 쪽이다**

반응이 2몰 → 1몰이므로 전환율↑ → 몰수↓ → 압력손실↓ → **출구압↑**. 즉 역방향 인과가 있다.
10/14에서 선행/후행을 확인했다.

```
전환율이 약 12분 먼저 움직일 때 상관 최대 = +0.984
동시                                      = +0.966
```

12분은 반응기 자체 응답(2~3분)이 아니라 **컬럼 → 재순환 → 반응기** 고리의 시간 규모다.
즉 10/14의 압력 변동은 재순환 표류의 **흔적**이지 원인이 아니다. 입력으로 쓰면 부분 누수다.

**뒤따르는 반문 — "그럼 압력이 중요하다면서 왜 안 넣나?"**

> 압력 효과를 넣으려면 **압력만 따로 흔든 데이터**가 필요한데 그런 캠페인이 없습니다.
> 지금 데이터로 압력 계수를 추정하면 유량 계수와 뒤섞입니다. 그래서 **압력이 학습 범위와
> 크게 다른 조건에서는 이 모델을 쓸 수 없다**는 한계로 명시했습니다. 케이스 스터디 조건은
> 압력이 학습 범위 안이라 이 한계에 걸리지 않습니다.

재현: `압력변수_제외근거_검증.py` (프로젝트 루트)

### 2-5. 10/12는 왜 학습·검증 어디에도 안 썼나

```
10/12  481행, 전부 동일 조건 (FT=3000, TT=341.57, FRC=5.0), 전환율 0.615885 일정
```

> 481행이지만 조건이 전부 같아서 **사실상 데이터 1점**입니다. 학습에 넣어도
> 새 정보가 없고, 오히려 그 한 조건이 481배로 과대 대표됩니다.
>
> 대신 **정상운전점 재현 확인용 기준점**으로 남겨뒀습니다. 모델에 10/12 조건을
> 넣었을 때 0.615885가 나오는지 보는 겁니다. 현재 오차 **−0.081%**로 통과했습니다.

### 2-6. r1 라벨의 결측 처리

재순환 큐멘 1 mol% 가정 라벨(r1)은 SRK 수치해가 수렴하지 않는 행이 생겨 NaN이 된다.
이건 제외한 게 아니라 **개수를 세어 보고**했다(`labels.py`가 실패 건수를 출력).

## 질문 3 (ex1). 유량만 바꿨는데 다른 변수가 흔들리면 어떻게 반영했나

**세 겹으로 대응했다.**

**① 설정값이 아니라 실측값을 입력으로 썼다**

> 저희는 지시값(SP)이 아니라 **실제 측정값(PV)** 을 입력으로 씁니다.
> "유량 실험이니까 온도는 341.57로 고정"이라고 가정하지 않고, 그 순간 실제로
> 341.62였으면 341.62를 넣습니다. **다른 변수가 흔들렸다면 그 흔들림이
> 입력값에 이미 들어와 있습니다.**

**② 세 변수를 동시에 입력으로 넣었다 (다변량 회귀)**

> 회귀분석은 원래 **여러 변수가 동시에 변할 때 각각의 기여도를 분리**하는 도구입니다.
> 온도 계수 b₁은 "유량과 비율이 같을 때 온도 1도당 효과"로 추정됩니다.

**②-1. 흔들림의 크기를 SP−PV로 측정해뒀다**

```
입구온도 |PV−SP| 평균 0.575°C   ← 상대적으로 잘 안 따라오는 변수
비율   |PV−SP| 평균 0.003     ← 거의 완벽히 제어됨
```

> 어떤 변수가 실제로 흔들렸는지를 **대회 제공 데이터의 설정값 컬럼으로 확인**했습니다.
> 흔들린 건 온도이고, 비율과 유량은 안정적이었습니다.

**② 캠페인 설계 자체가 한 번에 하나씩 바꾸도록 돼 있다**

```
10/13   FT-1004 2500~3071 스윕, FRC≈5.0 고정
10/14   전 변수 고정 (노이즈 바닥 측정용)
10/15   FT-1004 2500~3661 + FRC-1004 4.0~6.0
10/16   TT-1006 330~350 스윕 (20°C)
```

> 변수를 하나씩 분리해 스윕한 블록 설계입니다. 그래서 각 변수의 효과가
> 다른 변수와 섞이지 않고 식별됩니다.

**③ 남은 흔들림의 크기를 실측해뒀다**

> 10/14는 입구온도 변동폭이 **0.108°C**로 사실상 완전 고정인데도
> 전환율 표준편차가 **0.00307** 나옵니다. 이게 저희 데이터의 **변동 바닥**입니다.
> 현재 검증 RMSE 0.0209는 이 바닥의 약 7배입니다.

> **⚠ 2026-07-31 정정 — "노이즈"라고 부르지 말 것.**
> 이 변동은 잡음이 아니라 **설명 가능한 물리 변동**임이 확인됐다.
> 10/14에서 압력이 13.2 kPa(+0.52%) 움직였고, 적합된 속도식(r ∝ P^2.31)으로 계산하면
> 그만큼의 압력 변동은 **ΔX = +0.0137**을 만든다. 실제 관측 ΔX는 **+0.0097**로 같은 자릿수다.
> 그 압력 변동 자체는 재순환 고리의 표류가 만든 것이다(corr(X, TC-1215) = −0.7969,
> 선행/후행상 전환율이 압력보다 약 12분 앞섬).
> 따라서 "**모델이 절대 넘을 수 없는 한계선**"이 아니라 "**측정하지 않은 재순환 조성을
> 입력에 넣지 않았기 때문에 남는 변동**"으로 서술한다. 성능 판단 근거로는 쓰지 않는다.

## 질문 4 (ex2, ex3). 입구 조건에 출구가 즉시 반응하나? 수렴 시간은 고려했나

**잘 답할 수 있는 항목이다. 다만 "이미 반영돼 있다"고 답하면 안 된다.
최종 모델은 지연 보정을 넣지 않았다. 대신 지연을 전부 측정해 두었다.**

> **서술 원칙 (2026-07-31).** 이 절의 모든 숫자는 데이터에서 직접 읽은 값이다.
> 가정한 시정수, 가중치 함수, 임의로 그은 임계값은 쓰지 않는다.
> 상수는 두 개뿐이고 둘 다 출처가 한 줄로 설명된다 —
> **잡음 바닥 0.003068** (10/14 = 입력 3종 고정 캠페인의 X 표준편차) 와
> **정착시간 12분** (10/17 18:00 계단에서 X가 최종값 ±0.003068 안에 들어오기까지).

### 4-1. 즉시 반응하지 않는다 — 응답 시간은 측정값이다

> 반응기에는 **체류시간**과 **촉매층 열관성**이 있어서, 입구온도를 바꿔도
> 출구 전환율이 따라오는 데 시간이 걸립니다. 저희는 이 시간을 **가정하지 않고
> 데이터에서 측정**했습니다. 세 가지 독립적인 방법이 모두 **2~3분**을 가리킵니다.

### 4-2. 두 가지 지연을 구분한다

질문이 섞여 있으므로 먼저 나눠서 답한다. 우리 데이터에는 **성격이 다른 지연이 두 개** 있다.

```
지연 ①  운전원이 온도를 바꾸라고 지시 → 실제 입구온도가 그 값에 도달
         = 온도 제어 루프의 정착 시간          → 관측값 약 24~30분

지연 ②  입구온도가 실제로 바뀜 → 출구 전환율이 반응
         = 반응기 자체의 응답 시간             → 관측값 약 2~3분
```

**둘 다 원본 데이터에서 직접 측정된 값이고, 어떤 식도 가정하지 않았다.**

### 4-3. 지연 ① — 설정값(SP)과 실측값(PV)으로 측정했다

대회 제공 원본 CSV에는 **설정값(SP) 컬럼이 12개** 함께 들어 있다.

```
TC-1006.SP = 341.57   운전원이 "이 온도로 맞춰라"고 지시한 값
TC-1006.PV = 341.62   실제로 측정된 값
```

둘의 차이가 **제어 편차**이고, 공정이 아직 안 맞춰졌다는 뜻이다.
(참고: `TT-1006.PV`와 `TC-1006.PV`는 전 구간 완전히 동일한 값이다.
TT는 측정기, TC는 그 측정값을 읽는 제어기라서 그렇다.)

**관측 결과:**

```
입구온도 |PV−SP|    평균 0.575°C,  최대 8.255°C
비율   |PV−SP|    평균 0.003,   최대 0.244    ← 거의 완벽히 제어됨

SP 계단 변경 후 PV가 ±0.1°C 안에 들어오기까지
  341.57 → 340.00 : 30분
  341.57 → 350.00 : 24분
```

> 온도 지시를 바꾸면 실제 온도가 따라오는 데 **20~30분**이 걸립니다.
> 비율(FRC)은 평균 편차 0.003으로 거의 즉시 맞습니다.
> 즉 **흔들리는 변수는 온도이고, 유량·비율은 안정적**이라는 걸 데이터가 보여줍니다.

### 4-4. 지연 ② — 계단응답을 직접 봤다 (가장 강한 근거)

전 캠페인에서 **입력이 계단으로 바뀐 지점은 10/17 18:00 한 곳**이다
(FT-1004 : 2500 → 2778 kg/h, 분당 변화 153.8 kg/h). 그 구간을 그대로 보면 된다.

```
t(분)  TT-1006(°C)   X(r0)
 -1     341.56      0.4123
  0     339.46      0.4188
  1     338.90      0.4189   ← 입구온도 저점
  4     340.45      0.3944   ← X 저점 (3분 뒤)
 10     341.40      0.4425
 12     341.44      0.4477   ← 최종값 ±0.003068 안으로 진입 = 정착
 20     341.51      0.4512
```

> 입구온도가 최저가 된 시점에서 **3분 뒤**에 전환율이 최저가 됩니다. 이것이
> 반응기 응답 시간입니다. 완전히 정착하는 데는 **12분**이 걸립니다.
> 언더슛(먼저 내려갔다 올라감)까지 보이는 전형적인 공정 동특성입니다.

### 4-5. 지연 ② — 지연 스캔으로도 같은 값이 나온다

입구온도를 k분 전 값으로 바꿔 넣고 **최종 레시피(로짓 1차 선형 · I1 · r1)**의
검증 오차를 비교했다. 어떤 시정수도 미리 가정하지 않고, 최적점을 데이터가 고르게 했다.

```
[방법 1] 지연 스캔 — 입구온도를 k분 전 값으로 치환
  lag  0분  0.02099        lag  3분  0.01694 ←최적
  lag  1분  0.01863        lag  5분  0.02071
  lag  2분  0.01710        lag 10분  0.03684

[방법 2] 지수평활 τ 로 대표 입구온도 생성
  τ= 0분  0.02099          τ= 3분  0.01701 ←최적
  τ= 1분  0.01933          τ= 5분  0.01865
  τ= 2분  0.01757          τ=12분  0.03181
```

> 서로 다른 두 방법이 **모두 2~3분**에서 최소가 됩니다. §4-4의 계단응답에서 읽은
> 3분과도 일치합니다. **세 번째 독립 확인**입니다.
> 재현: `지연효과_검증.py` (프로젝트 루트)

### 4-6. 과도상태와 준정상상태를 어떻게 나눴나

임계값을 임의로 긋지 않았다. 데이터가 정해준 두 숫자만 쓴다.

```
잡음 바닥 = 0.003068
  10/14는 입력 3종(TT-1006·FT-1004·FRC-1004)이 전 구간 고정된 캠페인이다.
  아무것도 바꾸지 않았는데도 X가 이만큼 흔들린다 → 이것이 "변화 없음"의 폭이다.

정착시간 = 12분
  §4-4의 계단에서 X가 최종값 ±0.003068 안에 들어오기까지 걸린 시간.

판정: 직전 12분 창에서 X의 변동폭(max−min)이 0.003068을 넘으면 과도, 아니면 준정상.
```

**이 기준의 자체 검증** — 입력을 전혀 건드리지 않은 두 캠페인에서 과도가 0%로 나와야 한다.

```
캠페인        과도 비율
10/12          0.0%   ← 입력 고정. 기준이 옳다면 0이어야 함 ✔
10/14          0.0%   ← 입력 고정 ✔
10/13         51.8%
10/15         65.9%
10/16         71.9%
10/17-18      51.6%
```

10/17 18:00 계단은 **계단이 시작된 바로 그 분부터** 과도로 잡힌다.

### 4-7. 과도상태에서 오차가 실제로 커진다

최종 레시피(로짓 1차 선형 · I1 · r1)의 검증셋(10/17-18, 661행) 오차를 위 기준으로 나누면:

```
준정상  n=320   RMSE 0.01475   MAE 0.01096
과도    n=341   RMSE 0.02549   MAE 0.01807
전체    n=661   RMSE 0.02099   MAE 0.01463

→ 과도 구간 오차가 준정상의 1.73배
```

### 4-8. 그래서 모델에는 어떻게 반영했나 — 반영하지 않았고, 그 이유가 있다

> **최종 모델은 지연 보정을 넣지 않은 단순 모델입니다.** 측정은 다 해 놓고
> 일부러 넣지 않았습니다. 이유는 두 가지입니다.
>
> 첫째, **쓸 지점에서 효과가 없습니다.** 지연 보정은 입력이 변하는 중일 때만
> 의미가 있는데, 케이스 스터디(§3.3-6)는 전부 **정상운전 조건**의 예측입니다.
> 실제로 입력이 고정된 10/12 조건에서 정상운전점을 재현시켜 보면
> 예측 0.608124 / 실제 0.606376 (**+0.288%**)로 지연 보정 없이도 맞습니다.
>
> 둘째, **ONNX 인터페이스가 3-입력 정적 함수입니다.** 지연 보정을 넣으려면
> 모델이 과거 이력을 들고 있어야 하는데, 플로우시트가 부르는 것은 현재 값
> 3개를 넣으면 X 하나가 나오는 함수입니다. 상태를 갖는 모델은 이 인터페이스에
> 맞지 않습니다.
>
> 대신 **지연의 크기를 정량화해 한계로 명시**했습니다. 과도 구간에서 오차가
> 1.73배로 커진다는 것을 보고서에 그대로 기록했습니다.

**핵심 메시지:** 모르고 넘어간 것이 아니라, **측정하고 → 영향을 정량화하고 →
적용 지점에서 실익이 없음을 확인하고 → 의도적으로 단순한 쪽을 택했다.**

> **주의 (심사 대응).** "표본 가중치로 과도 구간을 낮게 반영했다"는 식으로 답하지 말 것.
> 데이터셋에 `ML_weight` 컬럼이 존재하지만 **최종 모델은 무가중이고 이 컬럼을 쓰지 않는다.**
> 가중/무가중 비교는 실험 기록(`results/`)에만 남아 있으며 성능 차는 0.0001로 무의미했다.

**Q. 검증셋 RMSE 0.0209면 좋은 건가?**
> 10/14 변동 바닥이 0.00307이므로 약 7배입니다. 남은 격차의 주원인은 모델 성능이 아니라
> **355~360°C 구간이 학습셋에 없다**는 데이터 범위 문제입니다.
> (변동 바닥을 "노이즈"로 부르지 않는 이유는 §3 정정 참조 — 상당 부분이 압력·재순환으로
> 설명되는 물리 변동이다.)

**Q. 등분산성은 만족하나?**
> 아닙니다. Breusch-Pagan·White·Goldfeld-Quandt 모두 p<0.001로 이분산입니다.
> 다만 등분산성은 OLS 계수의 **불편성** 조건이 아니라 **효율성과 표준오차 타당성**
> 조건입니다. 저희는 계수의 유의성 검정을 하지 않고 시간 분리된 홀드아웃 검증셋의
> RMSE로 평가하므로 결론에 영향이 없습니다. 잔차 구조는 별도로 분석해
> 구간별 편향을 정량화했습니다(`docs/img/residual_diagnostics.png`).

**Q. 365°C 운전이 실제로 가능한가? (후단 처리 한계)**

> **⚠ 먼저 꺼내지 말 것.** 질문을 받거나 시뮬레이션에서 문제가 생겼을 때만 사용한다.
> 우리 결과물은 반응기 전환율 예측이고 증류부는 모델 범위 밖이다.
> 먼저 언급하면 "그 구간 데이터를 학습에 썼느냐"는 불필요한 의심을 부른다.

받았을 때의 답:

> "확인해봤습니다. 후단 증류탑 액위(LC-1200)가 **큐멘 생산량 약 5,480 kg/h**에서
> 포화되기 시작합니다. 그 이상 구간은 예외 없이 액위 100%였습니다.
>
> 저희 모델로 환산하면 365°C에서 큐멘 8,298 kg/h가 나오는데, 이는 문턱의 **1.5배**이고
> 관측된 최대 생산량(7,070 kg/h)보다도 17% 많습니다. **병목은 반응기가 아니라 후단
> 분리 능력**입니다. 온도 상승안을 실제로 적용하려면 분리 능력 확보가 선행돼야 합니다."

근거 데이터:

```
큐멘 생산량 구간     액위 100% 포화 비율
4,500 ~ 5,000           0.0%
5,000 ~ 5,500           3.5%
─────────────────────────────  ← 문턱 ≈ 5,480 kg/h
5,500 ~ 6,000         100.0%
6,000 이상            100.0%

10/12 정상운전 = 5,115 kg/h → 포화 0회 (여유 있음)
```

인과 사슬(정상 구간 vs 포화 구간 비교로 확인):

```
입구온도 341→348°C  →  전환율 상승  →  큐멘 4,681→6,161 kg/h (+32%)
  →  증류탑이 못 빼냄  →  액위 100%
```

**라벨 건전성:** 포화 구간에서도 반응기 출구 밀도 36.20, 출구압력 2,444 kPa로 정상
범위다. 전환율 라벨은 반응기 출구 밀도로 계산하므로 하류 액위의 영향을 받지 않는다.

**주의 — 틀리기 쉬운 표현**

```
✗ "큐멘 생산량에 상한이 있다"   → 포화 중에도 5,475~7,070으로 계속 변한다. 상한이 아니라 문턱
✗ "AT-1201이 생산량"           → AT-1201은 밀도(kg/m³). 생산량은 FT-1201(kg/h)
✗ "352°C 이상 구간 프로펜 2700 이상" → 2700 '이상'이 아니라 2700 '에 고정'(2697~2704)
```

**Q. 365°C 예측은 믿을 수 있나?**
> 외삽입니다. 그리고 온도 축뿐 아니라 **유량 축에서도** 외삽입니다. 학습·검증
> 데이터에서 입구 352°C를 넘는 구간은 유량이 2697~2704로 고정돼 있어,
> 케이스 스터디 조건(유량 3000)과 조합된 데이터가 없습니다.
> 모델은 **가법성 가정**(온도 효과와 유량 효과가 독립)으로 이 빈칸을 메우고 있습니다.
> 이 한계를 명시하는 것이 정확한 서술입니다.
